# Return Relay 문구·영상 검토

세 차례에 걸쳐 수정하고 대조했다. 첫 검토에서 서비스 소개의 반복, 날짜 오해, 정형적인 도구 평가를 고쳤다. 두 번째 검토에서는 MCP 호출 경로와 날짜 입력 안내의 표현을 실제 동작에 맞추고, 오래된 시험 수와 피그마 설명을 수정했다. 마지막에는 영상과 저장된 신청 답변을 대조했다.

## 실제 수정

- 시작을 Alex의 금요일 여행과 목요일 반품 계획으로 바꿨다. 목요일은 반품 기한이 아니라 예정한 방문일이다.
- 같은 흐름을 세 번 설명하던 본문을 줄였다. 제출 문서 839→712단어, Product Feedback 1,160→849단어다. 문서 전체의 단순 공백 기준이며 개선율 지표가 아니다.
- Product Feedback은 공식 질문 다섯 개에 맞춰 다시 묶었다. 각 도구마다 반복하던 추천 문장을 없애고 실제 문제와 수정 내용을 남겼다.
- 영상 14개 장면의 자막을 짧게 고쳤다. 기존 실제 녹화본의 화면은 그대로 사용했다.
- 피그마의 옛 설명을 실제 귀가 시간 계산에 맞췄다. 수정한 프레임을 렌더링해 줄바꿈과 잘림을 확인했다.
- Devpost 추가 답변 8개와 소개 문구를 저장하고 다시 열어 원문과 대조했다. 본문은 수정본과 일치하지만 영상 URL이 없어 아직 저장되지 않았다. 이전 갤러리 이미지는 현재 앱 화면으로 교체했다.

## 도구 검사와 판정

write-good, alex, retext의 반복 단어·관사·문장 난도·대체어 검사를 실행했다. 같은 18개 입력에서 write-good 경고는 76→85, alex 경고는 36→33이었다. 경고 수를 낮추려고 정확한 표현을 바꾸지 않았다. 최종 검사는 추가 공개 문서와 영상 설명 등을 포함해 22개 입력을 확인했다.

`request`를 `ask`로, `host`를 `presenter`로 바꾸라는 제안은 소프트웨어 문맥에 맞지 않는다. 인물의 대명사, 저장 상태를 설명하는 수동태, 라이선스와 과거 시험 기록도 유지했다. `an x86_64`의 관사 경고는 발음상 맞지 않는 지적이다. 검토를 마친 경고와 유지 이유는 `after/retained-findings.json`에 남겼다. 이 검사는 작성 주체를 판별하거나 AI 판정 회피를 보증하지 않는다.

## 영상 및 회귀검사

영상은 155.234초이며 새 자막의 최대 속도는 초당 12.7자다. 14개 장면 중간 화면과 승인 창 7개를 직접 확인했다. 포장 항목·동의 버튼·반품 영수증·환불 미확인 상태가 자막과 맞았고, 전체 디코딩 오류는 없었다. 빌드와 서비스 시험 47개, 브라우저 시험 19개를 다시 실행해 통과했다. 앱 실행 코드는 배포본과 같다. 기존 배포 검사를 이번에 다시 수행한 것으로 집계하지 않았다.

마지막 검토에서 추가 수정이 필요한 항목은 발견하지 못했다. 공개 영상 업로드와 본문 저장, 최종 접수는 별도의 진행 상태로 남아 있다.
